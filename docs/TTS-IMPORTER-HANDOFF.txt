UVS ULTRA CUSTOM UI -> TTS DECK IMPORTER HANDOFF
=================================================

Purpose
-------

This Chrome extension modifies the Forum Code generated by UVS Ultra deck pages
so the TTS importer can distinguish cards that share a name but use images from
different sets or alternate-art releases.

UVS Ultra page involved:
https://uvsultra.online/deck.php?deck={deckKey}


Modified card-line format
-------------------------

Original UVS Ultra format:

    {quantity} {cardName}

Example:

    3 Walk The Dog

Extension format:

    {quantity} -{setId}/{cardNumber} {cardName}

Examples:

    3 -yyhdt/095 Walk The Dog
    3 -bl01/005 Walk The Dog
    1 -riseofmasters/028 ·Dr. Wily·
    1 -capcomleaguekit/010 ·Dr. Wily·

The hyphen immediately before setId and the slash before cardNumber are
intentional. setId is the directory name and cardNumber is the exact image
filename stem used by UVS Ultra under:

    https://uvsultra.online/images/extensions/{setId}/

The extension adds `-{setId}/{cardNumber}` to every exported card line, not only
cards with known alternate art. BBCode headings and other Forum Code content
remain unchanged.


Recommended importer parsing
----------------------------

Parse a modified card line as:

    ^\s*(\d+)\s+-([A-Za-z0-9_-]+)/([A-Za-z0-9_-]+)\s+(.+?)\s*$

Capture groups:

    1. Quantity
    2. UVS Ultra setId
    3. Exact UVS Ultra image filename stem
    4. Complete card name

Use the composite identity:

    setId + cardNumber + normalized card name

Do not key image selection by card name alone. Names are not unique across
printings, and UVS Ultra may collapse alternate printings under one canonical
card database ID.

For transitional compatibility, the importer may continue accepting the old
format when no -setId token exists:

    ^\s*(\d+)\s+(.+?)\s*$

The old-format fallback should retain the importer's existing name-only behavior.


Image resolution
----------------

A normal full-size image URL follows this pattern:

    https://uvsultra.online/images/extensions/{setId}/{cardNumber}.jpg?20240802

UVS Ultra also commonly provides:

    {cardNumber}-preview.jpg
    {cardNumber}-mini.jpg
    {cardNumber}-ci-micro.jpg

Both setId and cardNumber are included because alternate images can share a set
directory. The importer should resolve this qualified identity only against its
own known CardDB entries.

Do not construct or fetch arbitrary URLs from unvalidated Forum Code. Treat setId
as untrusted input, enforce the character allowlist above, and resolve it only
through importer-owned card data or an explicit allowlist.

Repository-hosted and transforming alternates
----------------------------------------------

Repository-hosted art uses a reserved qualifier:

    repo/{uvsUltraCardId}-{officialGalleryId}

Resolve this only through the packaged runtime catalog. Never turn the qualifier
itself into a URL. The catalog is pinned to an immutable Git commit and may map
one front qualifier to both a front image and a `transformBack` image.

Example:

    1 -repo/10964-2727 Eren Yeager, Promising Scout

That front qualifier resolves to gallery front 2727 and transformed back
`repo/10965-2799`, Attack Titan, Ferocious Challenger. Spawn/import logic must
preserve both allowlisted face URLs for gameplay. Do not expect or require a
second Forum Code line for the transformed face.


Current alternate-art mapping
-----------------------------

Canonical UVS Ultra card ID: 10509
Card name: Walk The Dog

Original:

    Label: Original
    setId: yyhdt
    cardNumber: 095
    Image: https://uvsultra.online/images/extensions/yyhdt/095.jpg?20240802

Alternate:

    Label: Alternate
    setId: bl01
    cardNumber: 005
    Image: https://uvsultra.online/images/extensions/bl01/005.jpg?20240802

The extension's deck-page action menu lets the user choose between these variants.
The selection is scoped by numeric deck ID plus canonical card ID. Choosing the
alternate causes Forum Code to contain:

    {quantity} -bl01/005 Walk The Dog

Choosing the original causes Forum Code to contain:

    {quantity} -yyhdt/095 Walk The Dog


How the extension determines setId
----------------------------------

For ordinary cards, the extension reads the actual same-origin card image path
rendered in the deck list and extracts setId plus cardNumber from this strict
path shape:

    /images/extensions/{setId}/{cardNumber}[-preview|-mini|-ci-micro].jpg

For known alternate-art cards, the selected variant comes from an explicit local
allowlist keyed by UVS Ultra's canonical numeric card ID. Stored browser data only
contains the selected allowlisted variant key; it cannot provide an arbitrary URL.

The extension's allowlists are maintained in:

    card-art.js
    remote-card-art.js


Requested alternate-art research output
---------------------------------------

Please produce a list of additional cards with alternate art or multiple image
identities. Return JSON using this exact shape so it can be reviewed and added to
card-art.js with minimal ambiguity:

[
  {
    "cardId": "10509",
    "cardName": "Walk The Dog",
    "variants": [
      {
        "label": "Original",
        "setId": "yyhdt",
        "cardNumber": "095",
        "imageUrl": "https://uvsultra.online/images/extensions/yyhdt/095.jpg?20240802"
      },
      {
        "label": "Alternate",
        "setId": "bl01",
        "cardNumber": "005",
        "imageUrl": "https://uvsultra.online/images/extensions/bl01/005.jpg?20240802"
      }
    ]
  }
]

Requirements for each returned entry:

1. cardId must be the canonical numeric UVS Ultra card ID used by deck.php.
2. cardName must exactly match UVS Ultra's displayed name, including punctuation.
3. setId must exactly match the image directory name.
4. cardNumber must preserve leading zeroes.
5. Every imageUrl must be HTTPS, same-origin under uvsultra.online, and confirmed
   to return an image successfully.
6. Include all known variants for that canonical card, including the original.
7. Do not infer a relationship from similar names alone. Verify that the images
   represent the same game card or an intentional alternate-art printing.
8. Note uncertain mappings separately instead of placing them in the confirmed
   JSON list.


Important UVS Ultra behavior
----------------------------

UVS Ultra's search backend uses DISTINCT frontid. A search returning one card does
not prove that only one image or printing exists. Walk The Dog demonstrates this:
the search UI returns yyhdt/095, while bl01/005 is a valid alternate image hidden
behind the same canonical identity.

Prefer verified image paths, deck markup, set data, or other direct evidence over
search-result counts.
